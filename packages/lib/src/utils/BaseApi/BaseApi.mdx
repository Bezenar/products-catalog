# BaseApi

`BaseApi` provides a protected `request` method for subclasses. It sends requests with the Fetch API, parses successful responses as JSON, and throws when the response status is not successful.

## Request options

- `path`: URL passed to `fetch`.
- `method`: `GET`, `POST`, `PUT`, or `DELETE`; defaults to `GET`.
- `headers`: request headers forwarded to `fetch`.
- `body`: optional value serialized with `JSON.stringify` when truthy.
- `transformResponse`: optional function called with the parsed JSON response. Its return value becomes the resolved request value.

`BaseApi` does not add headers automatically. Set `Content-Type: application/json` when sending a JSON body if the server expects it.

## Extend BaseApi

`request` is protected, so expose application-specific methods from a subclass:

```ts
import { BaseApi } from 'lib';

interface Product {
  id: number;
  name: string;
}

interface CreateProduct {
  name: string;
}

class ProductsApi extends BaseApi {
  getProduct(id: number): Promise<Product> {
    return this.request<Product>({
      path: `/api/products/${id}`,
    });
  }

  createProduct(input: CreateProduct): Promise<Product> {
    return this.request<Product, CreateProduct>({
      path: '/api/products',
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: input,
    });
  }

  getProductLabel(id: number): Promise<{ id: number; label: string }> {
    return this.request<Product, unknown, { id: number; label: string }>({
      path: `/api/products/${id}`,
      transformResponse: (product) => ({
        id: product.id,
        label: product.name.toUpperCase(),
      }),
    });
  }
}
```

When `transformResponse` is provided, the promise resolves with its return value instead of the raw
JSON. The first generic describes the parsed response; the third generic describes the adapted result.

## Response and errors

The `Res` generic describes the value returned by `response.json()` to TypeScript; it does not validate the response at runtime. For a non-OK response, `request` throws an error with the status, such as `Request failed with status 503`. Network errors from `fetch` and JSON parsing errors are also allowed to propagate.
