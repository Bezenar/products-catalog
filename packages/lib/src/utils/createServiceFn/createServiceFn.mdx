<Title>createServiceFn</Title>

`createServiceFn` wraps a function in a service runner. It forwards the function's arguments, awaits its result, and reports success or failure through callbacks. The wrapper infers argument and result types from the function you pass in.

## Types

```ts
createServiceFn<Args extends unknown[], Result>(
	fn: (...args: Args) => Result,
): (
	args: Args,
	options: T_ServiceOptions<Awaited<Result>, Adapted>,
) => Promise<void>
```

- **`fn`** accepts any function whose parameters are captured as the tuple `Args`. It may return a value directly or a `Promise`.
- **`args`** is a tuple matching the parameters of `fn`, in order. For a function `(id: number, includeDetails: boolean) => ...`, pass `[7, true]`.
- **`options`** requires `onSuccess` and `onError`. `adapter`, `onBeforeRequest`, and `onComplete` are optional.
- **`Result`** is the function's return type. `Awaited<Result>` is the resolved value used by the callbacks.
- **`Adapted`** is inferred from the adapter's return type when an adapter is provided. Without an adapter, `onSuccess` receives the original resolved result.
- **Return value:** the runner returns `Promise<void>`; the result is delivered to `onSuccess`, not returned from the promise.

The lifecycle is `onBeforeRequest` → function call → `onSuccess` or `onError` → `onComplete`. A rejected function call is passed to `onError` and is not rethrown by the runner.

## Pass through a result

Use this when the consumer needs the full resolved response. The callback parameters are inferred from the wrapped function:

```ts
import { createServiceFn } from 'lib';

type Product = {
  id: number;
  name: string;
};

const fetchProduct = async (id: number): Promise<Product> => ({
  id,
  name: 'Gateway',
});

const getProduct = createServiceFn(fetchProduct);

await getProduct([7], {
  onSuccess: (product) => {
    // product is inferred as Product
    console.log(product.name);
  },
  onError: (error) => {
    console.error(error);
  },
});
```

## Adapt a result

An adapter transforms the resolved value before `onSuccess`. The success callback is inferred from the adapter's return type:

```ts
const getProductName = createServiceFn(fetchProduct);

await getProductName([7], {
  adapter: (product) => product.name,
  onSuccess: (name) => {
    // name is inferred as string
    console.log(name.toUpperCase());
  },
  onError: (error) => {
    console.error(error);
  },
});
```

## Wrap a synchronous function

Synchronous return values are also supported. The runner still returns a promise and sends the value to `onSuccess`:

```ts
const double = createServiceFn((value: number) => value * 2);

await double([21], {
  onSuccess: (result) => {
    // result is inferred as number
    console.log(result);
  },
  onError: (error) => {
    console.error(error);
  },
});
```

## Lifecycle callbacks

```ts
await getProduct([7], {
  onBeforeRequest: () => console.log('Loading'),
  onSuccess: (product) => console.log(product),
  onError: (error) => console.error(error),
  onComplete: () => console.log('Finished'),
});
```

`onError` receives `unknown`, so narrow or inspect the error before using error-specific properties. `onBeforeRequest` and `onComplete` are optional.
